# Архитектура проекта «Нохчийн Мотт»

Документ объясняет, как устроен проект, простыми словами — для начинающего
разработчика, который будет его поддерживать и расширять.

## Почему Astro, а не React/Vue?

Игра достаточно проста по интерактивности (карточки, кнопки, аудио), поэтому
тяжёлый фреймворк не нужен. Astro даёт три важных преимущества:

1. **SSG (статическая генерация)** — на этапе сборки все страницы превращаются
   в готовый HTML. Это нужно для SEO/индексации (Этап 6) и для мгновенной
   загрузки без сервера.
2. **Минимум JavaScript** — по умолчанию Astro отдаёт страницы вообще без JS.
   Интерактив добавляется точечно (наши `src/scripts/` модули), что держит вес
   приложения в пределах требований (< 200 KB JS gzip).
3. **Простота** — `.astro`-файлы выглядят как обычный HTML с «вкраплениями»
   логики, плюс обычный vanilla JS. Порог входа низкий.

## Разделение данных и кода

Главный принцип: **контент не хардкодится в код**.

- Весь учебный контент лежит в `data/lessons/*.json`.
- Правила структуры описаны в `data/schema/lesson.schema.json` (JSON Schema).
- Чтобы добавить урок, достаточно отредактировать JSON — код менять не нужно.

На Этапе 2 появится модуль-«загрузчик данных», который читает все файлы из
`data/lessons/` и валидирует их по схеме (защита от опечаток и «битых» данных).

## Слои приложения

```
[ JSON-данные /data ]  ← контент (буквы, слова, темы)
        ↓ читает
[ JS-модули /src/scripts ]  ← игровая логика (очередь вопросов, очки, жизни)
        ↓ управляет
[ Astro-компоненты /src ]  ← интерфейс (кнопки, карточки, экраны)
        ↓ использует
[ Дизайн-система /src/styles ]  ← цвета, шрифты, компоненты (CSS-переменные)
```

- **Данные** ничего не знают про интерфейс.
- **Модули логики** не трогают DOM напрямую (чистые функции — их легко тестировать).
- **Компоненты** слушают события и зовут модули логики.

Такое разделение позволяет писать unit-тесты на игровую логику без браузера.

## Дизайн-система

- `src/styles/global.css` — токены (цвета, шрифты, отступы, тени) и базовые стили.
- `src/styles/components.css` — компоненты (кнопки, карточки, модалка, прогресс,
  сердечки, звёзды).

Все цвета заданы CSS-переменными в `:root` с комментариями о контрасте WCAG AA.
Чтобы изменить фирменный цвет во всём приложении, меняется одна переменная.

## Данные (схема)

Каждая тема — JSON-файл вида:

```json
{
  "schemaVersion": 1,
  "topic": {
    "id": "alphabet",
    "title": { "ru": "Алфавит", "ce": "Элп" },
    "order": 1,
    "items": [
      {
        "id": "letter-a",
        "type": "letter",
        "chechen": "А а",
        "russian": "а",
        "transcription": "а",
        "audio": "/audio/alphabet/letter-a.mp3",
        "image": "/icons/alphabet/letter-a.svg"
      }
    ]
  }
}
```

Поля:
- `schemaVersion` — версия схемы (для будущей миграции данных).
- `topic.id` — уникальный id темы.
- `topic.order` — порядок на карте уроков и разблокировки.
- `items[]` — карточки (буквы/слова/цифры/цвета). `type` указывает тип.
- `transcription` — приблизительная транскрипция русскими буквами (эталон —
  аудио носителя, не транскрипция).

## Безопасность по умолчанию

- Никакого `innerHTML` с пользовательскими данными — только `textContent`.
- Всё сохранение прогресса — в `localStorage` с валидацией схемы при загрузке
  (Этап 2/5).
- Минимум зависимостей + фиксированный lockfile (`package-lock.json`).
- Content-Security-Policy и security-заголовки — на Этапе 5.
